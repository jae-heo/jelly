# Jelly 백엔드 Goal 실행 지침

이 문서는 초기 백엔드 목표를 보관한 기록이다. 현재는 React 웹 터미널과 SSH 프로젝트도
구현되어 있다. 현재 기능과 실행 방법은 [README](../README.md), 검증 범위와 남은 제한은
[검증 기록](VERIFICATION.md)을 참고한다.

다음 내용은 Goal 모드에 그대로 전달할 수 있는 실행 프롬프트다.

> `/path/to/jelly`에 개인용 원격 터미널 서비스 **줼리(Jelly)**를 완성한다.
> 먼저 기존 코드와 AGENTS.md, 검증 기록을 읽고 완료된 작업을 반복하지 않는다.
> 독립 Git 저장소를 사용하고, 형제 프로젝트나 다른 서비스를 변경하지 않는다.
>
> 웹 UI는 후속 작업이다. 이번 목표는 Node.js/TypeScript 백엔드, 프로젝트별
> tmux 터미널 세션, HTTP API, 인증된 WebSocket 입출력·크기 변경,
> CLI 테스트 클라이언트와 배포 문서다. 프로젝트는 기존 서버 디렉터리를 등록한다.
> 프로젝트 경로는 셸 문자열에 삽입하지 말고 개별 인자로 전달한다.
>
> tmux는 전용 소켓과 설정을 사용한다. 접속 해제와 세션 종료를 분리한다.
> 백엔드 재시작 후 기존 세션에 재접속할 수 있어야 한다. 재부팅 시 프로세스
> 생존은 약속하지 않는다. 동시에 접속하면 최신 접속이 제어권을 갖는다.
>
> 로컬 개발은 loopback, 원격 사용은 서버 자신의 Tailscale IP에만 직접 바인딩한다.
> Tailscale VPN 내 HTTP/WebSocket으로 접속하며 Serve/HTTPS 활성화를 요구하지 않는다.
> 모든 인터페이스나 LAN·공인 IP에 바인딩하지 않는다. API 토큰과 WebSocket
> Origin 검증을 구현하고, 장기 토큰을 URL·로그·Git에 기록하지 않는다.
> 브라우저용 일회용 연결 티켓을 제공한다. 개인용이며 다중 사용자 격리는 범위 밖이다.
>
> 실제 tmux 프로세스를 이용해 다음 완료 조건을 검증하고 결과를 문서화한다.
> 1. 프로젝트 등록·조회·삭제와 경로 검증.
> 2. 해당 디렉터리에서 세션 생성, 조회, 명시적 종료.
> 3. 인증 실패·잘못된 Origin·잘못된 입력·티켓 재사용 거부.
> 4. WebSocket으로 명령 입력, Unicode 출력, 터미널 크기 변경.
> 5. 연결 해제 후 작업 지속 및 재접속 화면 복구.
> 6. 백엔드 종료·강제 종료·재시작 후 동일 셸 PID로 재접속.
> 7. 새 접속의 제어권 인계와 이전 연결 정리.
> 8. 셸 자연 종료와 서버 재부팅 등으로 사라진 세션의 상태 구분.
> 9. 느린 클라이언트에 대한 메모리 제한과 연결 정리.
> 10. 실행 방법, API 계약, Tailscale 배포, 토큰 취급, 스크롤백 한계 문서화.
>
> 가능한 환경에서는 서비스를 실행하고 로컬·Tailscale 경로를 확인한다.
> 실제 휴대폰 테스트를 하지 못했다면 했다고 주장하지 않는다. Codex/Claude
> 실계정 호출이나 유료 작업 없이 PTY 및 대화형 프로그램 동작을 검증한다.
> 기능 구현과 검증이 끝난 경우에만 Goal을 완료한다. 실패·남은 제약은 솔직히 기록한다.
